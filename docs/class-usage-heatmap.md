# 학급 사용 히트맵과 활동 순서 변경

## 사용 위치

- 학급 관리 → 사용 히트맵: 최근 7/14/28일, 종료 날짜, 학생 검색, 학생×날짜 / 학생×기능 전환. 칸을 눌러 상세 시간을 확인한다. 조회는 화면을 열거나 기간/새로고침을 선택할 때만 실행한다.
- 차시의 교사 활동 편집 → 활동 순서 변경: 현재 수업 전/후 활동을 모달에서 드래그하거나 위/아래 버튼으로 이동하고 저장한다. 취소는 변경하지 않는다. 기존 본문 드래그도 유지한다. 순서 저장은 원자적 update 배치로, 삭제된 활동을 빈 문서로 되살리지 않는다.

## 사용량 수집

학급 컨텍스트가 있는 화면의 학생만 수집한다. 기존 ClassLive의 멤버 역할 판정을 재사용한다. URL로 기능을 분류하며 열린 게임/퀴즈런은 해당 기능으로 분류한다. 별도 학급 정보가 없는 독립 페이지는 수집하지 않는다.

화면이 보이고 포커스가 있으며 최근 60초 안에 입력이 있을 때 10초 간격으로 브라우저에서 시간을 추정한다. 클릭 위치, 입력 문자열, 화면 녹화는 수집하지 않는다. 시간은 5분 구간별로 누적한다. 완성된 구간을 전송하고, 화면 이탈 시 부분 구간을 최선 노력으로 전송한다. 이탈 전송이 실패하면 로컬 대기열에서 다음 방문에 재시도한다. 처음 입력 전·숨김·비포커스·60초 이상 무입력 시간은 제외한다. 종료 직전 10초 미만은 누락될 수 있다.

지원 브라우저에서는 Web Locks와 사용자별 로컬 타임스탬프로 동일 브라우저의 탭 간 중복을 줄인다. Web Locks가 없으면 포커스 판정과 서버 병합으로 제한한다. 서로 다른 기기의 동시 사용을 완전히 식별하지는 않으며, 서버가 구간별 총합을 300초로 제한한다. 서버는 기존 값보다 큰 기능별 누계만 추가하고 재전송으로 시간을 다시 더하지 않는다. 이 수치는 출석/성적/이해도 판정용이 아니다.

## 권한과 비용

`recordClassUsage`: 로그인 사용자의 UID만 사용하고 해당 학급의 학생인지 서버에서 확인한다. 최대 12구간, 최근 7일, 허용 기능, 정수 초, 구간당 300초 및 경과시간 한도를 검증한다. 학생/일별 문서 `classes/{cid}/usageDays/{day}_{uid}`를 트랜잭션으로 갱신한다. 같은 값 재전송은 쓰지 않는다.

`getClassUsage`: 해당 학급 교사만 조회한다. 최대 28일, 2,000문서로 제한하고 초과 시 화면에 안내한다. 응답에는 세부 구간(buckets)이 없다. 클라이언트 직접 접근을 허용하는 규칙을 추가하지 않았다. buckets/counts 인덱스를 제외하는 설정을 추가했다.

30명×40분 활동 기준, 5분 저장의 기본 쓰기는 약 240회/학급이다. 멤버 검증·문서 읽기·함수 실행·부분 전송·재시도·교사 조회는 별도다. 30명×14일 기록이 있으면 교사 조회당 약 420개의 일간 문서를 읽는다. 여러 칸을 클릭하거나 모드를 전환하는 것은 추가 서버 조회를 하지 않는다.

로컬 미전송 대기열은 최근 7일/최대 288구간으로 제한한다. 일간 서버 요약은 현재 자동 삭제하지 않는다. 장기 운영 시 학교의 보관기간 정책에 맞춘 정리가 필요하다. 과거 활동은 소급 수집하지 않는다.

## 검증 및 배포

타입 검사, 웹/Functions 빌드, 새 컴포넌트 린트, 가짜 Firestore 기반 권한/중복/범위 검증 및 가짜 브라우저 기반 무입력/백그라운드/5분 저장 테스트를 수행했다. 실제 학생 계정의 운영 환경 검증은 별도다.

```sh
npm --prefix functions run build
node --test tests/usage.test.cjs tests/usage-tracker.test.cjs tests/activity-order.test.cjs
npm run build
firebase deploy --only functions:recordClassUsage,functions:getClassUsage,firestore:indexes
firebase deploy --only hosting
```

이 작업에서는 배포하지 않았다. Functions를 배포하기 전에는 사용량 전송이 실패해 로컬 대기열에 남고, 교사 화면에 조회 오류가 표시된다.
