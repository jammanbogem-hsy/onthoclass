## 사용 흐름

- 교사: 러닝크루 Google 로그인 → 기존 `users/{uid}.role == teacher` 확인 → 공방 개설 → 초대 링크 전달.
- 학생: 초대 링크/코드 → 별명과 PIN → 제작 카드·그림 첨부 → 제출.
- 교사: 승인/반려 → 승인한 스냅샷으로 생성. 요청별 최대 세 번의 시도를 허용한다.
- 학생: 생성 결과 확인 → 보관함 저장 → 모든 월드 편집기의 ‘공방 에셋’에 자동 등록. ‘에셋 모음’에서 PNG를 다운로드하고, 인물 에셋은 내 아바타로 선택한다.

교사 역할은 서버에서 확인한다. 학생·교사의 세션은 Firebase Hosting이 전달하는
`__session` HttpOnly 쿠키를 사용한다. API와 파일은 `/api/jamworld/**` 경로로 접근한다.
Sites 로그인, Cloudflare 신원 헤더, D1/R2 바인딩은 사용하지 않는다.

## 저장과 생성

- `src/features/jamworld`: 클라이언트 공방·편집기·플레이 및 Canvas2D 엔진.
- `functions/src/jamworld`: HTTP 라우터, Firebase 신원 확인, 공방 서비스, Firestore 어댑터.
- `jamworldApi`: Firebase Hosting rewrite의 HTTP 대상.
- `jamworldGenerate`: `jamworldGenerations/{id}` 생성 이벤트를 처리하는 서버 작업.
- `jamworld*` Firestore 컬렉션은 Admin SDK만 사용하며, 기존 클라이언트 규칙의 기본 거부가 적용된다.
- 원본 그림과 저장 전 생성 결과는 Storage의 `jamworld/`에 비공개 저장된다. 서버가 본인/담당 교사 권한을 확인한다.
- 보관함에 저장한 승인 결과는 공용 에셋 목록과 공개 그림 경로로 제공한다. 원본 첨부 그림은 공개하지 않는다.
- 이메일이 인증된 Firebase 신원 `jammanbogem@gmail.com`만 공용 에셋을 삭제할 수 있다. 삭제 이력은 `jamworldModeration`에 기록한다. 삭제하면 공용 목록·개인 보관함·아바타 선택·PNG 다운로드에서 제외한다. 삭제된 인물을 선택한 학생은 다음 조회 때 기본 탐험가로 돌아간다.
- 새 공방 인물은 방향별 대기·걷기 스프라이트로 생성한다. 위에서 보기는 4방향×5동작, 입체로 보기는 8방향×5동작이며, ‘내 아바타’와 생성 결과에서 걷기 미리보기를 제공한다.
- PNG는 서버의 Sharp로 변환해 투명 배경을 유지한다. 시점별 변환 결과는 비공개 Storage에 캐시하며, 다운로드마다 삭제 여부를 확인한다.
- 생성 시작·실행 claim·보관함 저장은 트랜잭션을 사용한다. 새로고침이나 중복 클릭으로 같은 시도가 중복 과금되지 않는다.
- 생성은 브라우저와 독립적으로 실행된다. 요청·승인·생성 준비·실행·완료는 권한이 확인된 변경 알림으로 화면에 반영된다.
- 도우미 대화는 학생별 시간당 30회, 입장 시도는 IP별 5분당 40회 제한한다.
- 기존 Secret Manager의 `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`를 서버에서만 사용한다.

## 요청 전달과 생성 시작

교사 10초·학생 8초 간격의 목록 갱신 대신, 화면이 보이는 동안 서버에 변경 알림 연결을 하나 유지한다. 요청 저장과 함께 `jamworldWorkshopSignals`의 학급·학생별 순번을 같은 트랜잭션/배치에서 올린다. Firestore 알림이 도착하면 권한이 있는 학급 또는 본인 요청만 전달한다. 생성 대기→실행→완료도 같은 방식으로 반영한다. 20초 동안 변경이 없어도 한 번 갱신해 이전 버전 작업과 연결 복구를 처리한다. 탭을 숨기거나 공방을 나가면 연결을 취소하고, 복귀하면 즉시 새 목록부터 받는다. 대기 후에는 역할·세션을 다시 확인한다.

**승인하고 생성**은 `/requests/{id}/generate`에 `approveRev`와 멱등 키를 한 번 보내며, 제출 버전 확인·승인 스냅샷 고정·생성 대기 등록을 한 트랜잭션으로 처리한다. **승인만**은 그대로 승인만 한다. 버튼 중복 실행은 브라우저와 서버에서 모두 막는다. 생성 준비와 실제 실행을 구분해서 표시한다. 이미지 제작과 실행 서버의 시작 시간 자체가 없어지는 것은 아니며, 작업 로그의 `queueWaitMs`로 대기 등록 이후 실행까지의 지연을 확인한다.

교사 확인 때 기존 교사 행에 대한 불필요한 쓰기 트랜잭션을 없앴다. 요청 목록을 두 번 조회하지 않고, 생성한 적이 없는 초안에 대한 생성 기록 조회도 생략한다. 새 생성 기록은 요청 행의 ID에서 직접 찾고 기존 기록은 이전 조회 경로를 유지한다. 선택한 공방의 학생 수와 대기 건수도 변경 알림에 포함한다.

검증은 핵심 테스트 69개, 서버 통합 18개, 실제 교사·학생 브라우저 흐름과 단일 요청 승인·생성/중복 클릭/숨김·복귀 시나리오를 포함한다. 로컬 에뮬레이터에서 제출→교사 알림 38ms, 승인→생성 대기 및 학생 알림 41ms를 확인했다. 운영 환경의 보장 시간이 아니라 고정 갱신 주기를 기다리지 않는지 확인한 측정값이다. `JAMWORLD_TEST_IMAGES=1 node scripts/jamworld/preview.cjs`는 가짜 이미지 키를 사용하고 네트워크 이미지 생성을 차단한 로컬 검증 서버다. `node --test scripts/jamworld/workshop-live.test.cjs`와 `workshop-live-browser.test.cjs`로 재현한다. 실제 학생 기록이나 유료 이미지 API는 검증에 사용하지 않는다.

2026-10-22 API·생성 작업·Hosting을 함께 배포했다. 배포 화면에서도 공방 API를 모의 응답으로 대체한 별도 브라우저로 단일 승인·생성 요청, 상태 알림, 탭 복귀를 확인했다. 실제 API의 익명 목록 조회는 `401`, 익명 승인·생성은 `403`으로 차단된다.

## 인물 스프라이트

학생이 분류를 **인물**로 고르면 방향과 동작을 따로 요청하지 않아도 걷는 아바타를 만든다. 생성 호출은 두 시점에 한 번씩이며, 각 응답은 여러 동작을 담은 투명 PNG다. 위에서 본 결과의 대기 그림을 입체 결과의 디자인 참조로 전달한다. 서버는 투명 영역으로 분리된 실제 인물을 찾아 행·열로 정렬하고, 모든 동작에 같은 크기 배율과 발 기준선을 적용한다. 바깥 여백이 달라도 잘리지 않도록 처리하며 비어 있거나 붙은 인물, 불투명 배경, 완전히 반복된 걷기 그림은 생성 실패로 표시한다. 자동 유료 재시도는 하지 않는다.

새 정규화 시트는 프레임 128×160px, 가로 5칸이며 세로 4칸/8칸이다. 열은 대기·왼발 접지·오른발 통과·오른발 접지·왼발 통과이며, 걷기는 1→2→3→4 순서로 재생한다. 탑뷰 행은 남·서·북·동, 입체 행은 남·남서·서·북서·북·북동·동·남동이다. 정규화 때 머리·상체 중심을 기준으로 가로 위치를 맞춰 팔과 발이 움직일 때 몸 전체가 좌우로 튀는 현상을 줄인다. 기존 4열 스프라이트도 원래 규격으로 재생한다. 학생 프로필에는 기존처럼 에셋 ID만 저장하고, 시트 URL과 규격은 서버가 활성 매니페스트에서 확인해 전달한다.

입체 기본 탐험가도 8방향×5동작 시트를 사용한다. `imagegen`으로 만든 원본은 `design/jamworld/iso-avatar-walk-v2-source.png`에 보관하며, `node scripts/jamworld/build-walk-atlas.cjs`로 공방과 같은 정규화를 재현한다. 원래 그림과 메타데이터도 보존했다. 실제 이동 128px마다 좌우 보행 한 주기를 재생하고 접지 자세를 통과 자세보다 오래 유지한다. 입체 이동 속도는 줌 1 기준 204.8px/초이며 약 0.15초 동안 출발을 완화한다. 방향 경계의 작은 조이스틱 흔들림은 같은 방향을 유지하고, 약한 입력은 천천히 걷는다. 입력을 놓거나 교사가 멈추거나 벽에 막히면 즉시 대기로 돌아가며, 그림 전체를 위아래로 튕기는 별도 효과는 쓰지 않는다. 위에서 보기도 기존 이동 속도를 유지하면서 실제 이동량으로 박자를 맞춘다.

공방 인물 생성은 기준 방향만 그리도록 수정했다. 위에서 보기는 정면·오른쪽 옆면·뒷면의 3행, 입체 보기는 정면·앞쪽 오른쪽·오른쪽 옆면·뒤쪽 오른쪽·뒷면의 5행을 받는다. 각 행은 대기와 걷기 4동작의 5열이다. 각도를 정면 0°·앞쪽 오른쪽 45°·옆면 90°·뒤쪽 오른쪽 135°·뒷면 180°로 명시하며, 해당 줄의 모든 칸에서 머리·가슴·시선 각도를 유지한다. 학생의 설명이나 참고 이미지가 다른 방향을 요구해도 외형만 참고하고 이 방향 계약을 우선한다. 방향 행 순서는 프롬프트와 이미지 처리에서 같은 상수를 사용한다. 정규화 과정에서 해당 오른쪽 프레임을 개별 반전해 왼쪽 방향을 만들고 기존 4방향/8방향 출력 시트로 확장한다. 전체 행이나 걷기 순서를 반전하지 않는다. `construction: canonical-mirrored-v1`로 구분하며 기존 4열/5열 완성 시트도 계속 읽는다. 생성 요청은 기존과 같이 두 시점 2회이고, 보정·반전 과정에서 유료 이미지 호출을 추가하지 않는다.

새 기준 방향 시트는 정확히 15/25개 인물인지 검사하며, 남는 인물을 버리고 정상 결과로 처리하지 않는다. 상반신의 알파·색상 유사도로 앞뒤 중복과 다른 방향의 대기 그림에 확연히 가까운 걷기 프레임을 거르는 보수적인 검사를 추가했다. 실패는 생성 실패로 표시하고 보관함 저장을 차단하며 자동 유료 재시도는 하지 않는다. 위에서 보기 검사에 실패하면 입체 그림 호출도 시작하지 않는다. 이 검사는 복제·명백한 방향 섞임을 거르는 휴리스틱이며 얼굴 의미나 정확한 각도를 판독하는 비전 모델 검사는 아니다. 미세한 방향 오류까지 보증하지 않는다. 생성 결과와 마이페이지 미리보기의 **앞·뒤 / 왼쪽·오른쪽 / 대각선** 버튼으로 두 시점의 모든 방향을 확인할 수 있다.

방향 시트를 불러오는 동안에는 방향을 지원하는 기본 캐릭터를 표시하며, 움직임 없는 정면 썸네일로 대체하지 않는다. 위에서 보기의 벽 미끄러짐은 실제 이동 방향을 바라보고, 시점 전환 시 이전 입체 방향을 잘못 재사용하지 않는다. 기존 5열 생성 시트는 왼쪽 행에 오른쪽 그림이 중복된 경우를 보완하도록 오른쪽 짝 프레임을 반전해 표시하며, 이미 확장된 새 시트와 이전 4열 시트는 자체 프레임을 사용한다. 기존 헤드셋 러너의 보정 원본·프롬프트는 `design/jamworld/headset-runner-direction-v3.md`, 실제 4/8방향 시트는 `design/jamworld/headset-runner-v3/`에 있다. `scripts/jamworld/repair-character-directions.cjs`는 먼저 로컬 변경안을 만들고 명시적인 `--apply`일 때만 새 불변 파일을 업로드한 뒤 해당 인물 매니페스트를 비교·갱신한다. 원본 파일은 보존하며 에셋 ID·기존 사용자 선택은 유지한다.

배치용 그림과 기존 PNG 다운로드는 대기 동작을 사용한다. **위에서 본 동작 ↓**, **입체 동작 ↓**는 전체 스프라이트 PNG를 내려받는다. 시트도 저장 전에는 비공개이며 저장·관리자 삭제 정책을 그대로 따른다.

기존 단일 그림과 아바타 선택은 유지한다. 해당 인물의 **걷는 아바타로 만들기**를 누르면 원래 그림을 복사해 새 제작 초안을 열며, 학생 제출→교사 승인→생성→저장 절차를 따른다. 기존 에셋을 덮어쓰거나 자동 생성하지 않는다. 자동 검사는 그림의 분리·투명도·크기·반복 구조와 명백한 앞뒤 복제·방향 섞임을 확인한다. 인물의 동일성과 세밀한 방향·보행 자세의 품질은 생성 결과의 방향별 걷기 미리보기에서 확인한다.

이전 4열 규격은 실제 AI 인물의 16+32개 동작으로 확인했다. 새 5열 규격은 기본 탐험가의 40개 동작과 테스트 provider의 20+40개 동작으로 정규화·저장·다운로드를 확인하며, 공방의 유료 API를 추가 호출하지 않는다. 브라우저 검증은 선택·저장·실제 방향 전환과 걷기 프레임·정지 프레임·시트 PNG 다운로드·기존 인물 재제작 초안·관리자 삭제 후 접근 차단을 포함한다. 반복 검증에는 `character-fixture.cjs`의 테스트 전용 그림을 사용한다. `JAMWORLD_CHARACTER_FIXTURE_DIR`의 실제 생성 샘플은 현재 규격에 맞는 5열 시트여야 한다. `live-character.test.cjs`는 `JAMWORLD_LIVE_CHARACTER=1`로 명시적으로 실행하는 유료 이미지 API 확인용이다.

보행 개선 검증은 핵심 테스트 67개, 서버 통합 테스트 13개, 브라우저 시나리오 5개를 포함한다. `walking-browser.test.cjs`는 새 손님 브라우저의 로컬 맵만 사용해 실제 렌더러의 8방향·네 동작 순환·프레임 크기·이동 속도·정지 후 위치 유지를 검사한다. `JAMWORLD_ORIGIN`으로 배포 주소에서도 같은 검사를 수행할 수 있으며, 이때 공방 API는 모의 응답으로 대체해 실제 학생·에셋 기록을 쓰지 않는다. 공방 브라우저 시나리오는 새로 저장한 인물의 네 동작과 개인 색이 두 시점 모두에 적용되는지도 확인한다.

보행 개선의 API·생성 작업·Hosting 배포를 완료했으며 배포 주소에서도 위 8방향 브라우저 검사가 통과했다. 기존 공용 ‘손오공 캐릭터’는 유지됐고, 실제 생성 API나 학생 데이터 변경 없이 검증했다.

2026-10-21 HTTP API·생성 작업·메인 Hosting을 함께 배포했다. 배포 화면에서도 별도 브라우저의 모의 학생 응답과 생성 샘플만으로 방향 전환·걷기·대기를 확인했으며 실제 학급·학생·에셋 데이터는 변경하지 않았다. 기존 공용 에셋 조회와 익명 재제작 요청 차단(`401`)도 확인했다.

## 아바타 색상

기본 탐험가의 옷·가방·신발 색 변경을 유지하며, 공방 인물에는 **내 인물 색 바꾸기**를 제공한다. **바꿀 색**에서 원본 색을 고르고 **새 색**에서 원하는 색을 누른 뒤 아바타를 저장한다. AI 이미지 재생성·도우미 호출·새 이미지 저장 없이 브라우저에서 처리하므로 색상 변경에 따른 AI 생성 비용은 없다. 새 인물 제작과 기존 인물에 동작을 추가하는 작업은 교사 승인 후 생성하는 기존 절차다. 인물의 기본 제작 형식은 계속 스프라이트다.

두 시점에서 최대 네 가지 대표 색을 찾고, 고른 색과 가까운 색상을 전체 프레임에 함께 적용한다. 옷·머리·피부의 의미를 자동 분리하는 방식은 아니며, 같은 계열의 색은 같이 바뀔 수 있다. 투명도·흰 부분·어두운 윤곽을 보존하고 명암 차이를 유지한다. 원래대로 버튼은 원본에서 다시 그리며, 반복 변경으로 색이 누적되지 않는다. 기존 단일 그림 인물도 같은 색상 편집과 두 시점 미리보기를 지원한다.

학생 프로필에는 `assetColors: [{source: 0..359, target: AvatarColor}]`만 최대 네 개 저장한다. 서버는 정수 범위·허용 색·중복·개수를 검증하고, 클라이언트가 보낸 이미지 URL이나 기타 필드는 저장하지 않는다. 공용 에셋·다른 학생의 아바타·원본 PNG 다운로드는 변경하지 않는다. 인물이 삭제되면 개인 색상 설정도 아바타 응답에서 제외한다. 실제 맵은 색을 적용한 시트를 한 번 계산하고 최대 두 장 캐시해 이동 프레임에서는 잘라 그리기만 한다.

검증은 기본 옷 색 변경, 투명·윤곽 보존, 명암, 중복 색 변환 방지, 서버 입력 제한과 함께 공방 인물 색 선택→프로필 저장→새로고침 유지→실제 맵의 색상 적용된 걷기 시트→이전 인물 편집·복구→모바일 배치를 다룬다. 색 선택·저장 중 생성/도우미 API 요청이 없는지도 확인한다. 이번 기능 검증은 이전에 만든 샘플과 로컬 테스트 그림을 재사용하며 유료 이미지 API를 호출하지 않는다.

색상 기능의 HTTP API와 Hosting도 배포했다. 배포된 화면에서 모의 학생 응답·이미지 파일만 제공하는 별도 브라우저로 실제 보라색 픽셀, 저장·새로고침 유지, 색을 적용한 걷기·대기, 유료 API 호출 0회를 확인했다. 실제 서비스의 익명 색상 프로필 변경은 `401`로 거부되며, 실제 학생·공용 원본 데이터는 검증 중 변경하지 않았다.

개인 맵 프로젝트는 사용자별 **현재 브라우저 저장소**에 저장된다. 교사가 공방에 공유한 수업 월드는 검증된 서버 스냅샷으로 저장되어 학생들이 다른 기기에서도 같은 맵 구성을 불러온다. 채팅·교사 제어·자연어 및 JavaScript 공간 효과는 [수업 기능 문서](jamworld-classroom.md)를 참고한다. 기기를 옮길 때는 프로젝트 JSON으로 내보내고 가져온다.
공방 기록·그림·아바타는 서버에 저장된다. 이전 Sites 운영 사이트의 맵은 그 사이트에서 내보내야 한다.
이전 D1/R2 학생 계정·공방 그림 데이터는 자동 이관하지 않았으며, 기존 사이트의 초대 링크는 여기서 사용할 수 없다.
이전 서버의 사용자 에셋은 파일 이관 없이는 그림을 그대로 가져올 수 없다.

## UI

Apple [Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/liquid-glass)의 탐색 계층·콘텐츠 분리 원칙을 웹 CSS로 적용했다.
상단 탐색과 도구 패널에는 반투명·배경 블러·하이라이트를 사용하고, 작업 카드는 읽기 쉬운 바탕을 유지한다.
동작 감소, 투명도 감소, 대비 증가 설정 및 `backdrop-filter` 미지원 환경에 대응한다.
Apple 네이티브 프레임워크나 네이티브 Liquid Glass API를 웹에 탑재한 것은 아니다.

[REA](https://github.com/morluto/rea) 6.7.0 CLI로 원본 JavaScript 모듈 구조를 분석하고, Chrome 시나리오로 첫 화면과 접근성 트리를 검증했다.
앱 런타임에 REA가 포함되지는 않는다. OpenAI SDK, 테스트용 Playwright Core·tsx, 로컬 Firebase 에뮬레이터용 OpenJDK 21을 사용한다.

## 기본 바닥 재질

기본 9종 바닥은 `lib/render/terrain.ts`의 Canvas 그림으로 제공한다. 잔디·짙은 잔디는 넓게 이어지는 색 변화와 작은 풀잎, 흙·모래는 따뜻한 색과 잔돌, 돌바닥은 엇갈려 놓인 둥근 판석과 약한 모서리 명암, 나무는 판재와 나뭇결, 카펫은 얇은 직물 결, 코랄은 둥근 도기 타일을 사용한다. 물에는 깊이에 따른 색과 여러 형태의 반사광, 얕은 물가와 둥근 모서리를 그린다. 기존의 타일별 체커 밝기와 반복되는 S자 물결은 없앴다.

무늬와 색 변화는 월드 좌표로 고정하며, 위에서 보기·입체 보기·편집기·에셋 썸네일에 같은 재질을 투영한다. 물가는 실제 상하좌우 이웃의 색을 따르며, 잔디와 길·광장이 만나는 가장자리에는 작은 풀잎이 겹친다. 바닥을 칠하면 인접 청크도 한 칸의 여유를 두고 갱신해 물가가 남는 현상을 막는다. 기본 바닥의 ID·이동 가능 여부·저장 형식은 바뀌지 않으므로 기존 월드에도 적용된다. 공방에서 만든 바닥 그림은 그대로 사용하며 체커 밝기 효과만 제거한다.

재질은 기존 바닥 청크 캐시에 한 번 그리며 매 프레임 다시 계산하지 않는다. 추가 런타임 라이브러리나 이미지 생성 API는 사용하지 않는다. 핵심 테스트 69개와 실제 Canvas 검사로 잔디·물 타일의 이음선, 두 시점의 인접 청크 갱신, 공방 텍스처 색 보존을 확인한다. `node --test scripts/jamworld/terrain-browser.test.cjs`로 Canvas 검사를 재현한다.

2026-10-22 Hosting 배포를 완료했다. 실제 배포 주소의 별도 손님 브라우저에서 두 시점의 숲속 광장을 확인했으며, 실제 공방 기록은 변경하지 않았다. 배포 화면은 `design/jamworld/terrain-v2-preview.png`에 보관한다. 모바일 지도 도구·상호작용과 실제 8방향 보행 시나리오도 통과했다.

## 마이페이지와 기본 아바타 (2026-10-22)

`/jamworldmake/?view=profile`에서 학생과 교사 모두 공방에 저장된 인물을 고르고 **내 아바타로 저장**한다. 에셋 모음과 공방의 저장 완료 화면에서도 특정 인물을 선택한 마이페이지로 이동한다. 선택만으로 계정 설정을 바꾸지 않으며 미리보기와 명시적 저장을 구분한다. 기존 `view=workshop&tab=avatar` 주소는 같은 마이페이지를 연다. 메인 앱 `/level`에도 아바타 설정 링크를 추가했다.

서버는 로그인한 교사/학생 자신의 설정만 저장한다. 클라이언트가 전달한 이미지 URL·스프라이트 메타데이터는 저장하지 않고, 공개된 활성 인물 에셋의 ID에서 다시 확인한다. 삭제된 인물은 다음 조회에서 기본 탐험가로 돌아간다. 맵은 두 역할 모두 저장된 아바타를 사용한다. 색 변경은 브라우저 연산이며 이미지 재생성 비용이 없다.

## 대화로 수업 맵 제작

편집기 **수업에 맞춰 만들기** 또는 `/grill-me 수업 주제`로 인원·시간·목표·활동 순서·추가 조건을 받는다. 모델은 부족한 정보를 최대 3개 질문으로 반환하며, 질문 단계에는 맵 변경이나 이미지 요청을 섞을 수 없다. 후속 답변과 현재 맵을 다시 보내 실제 변경안을 만든다. 대화·수업 조건·공방 제작 요청 ID는 계정별·프로젝트별·맵별 브라우저 저장소에 보관하고, 이미지 제작 상태는 기존 서버 공방 기록에서 이어받는다.

`resize`는 최대 120×120까지 오른쪽·아래로 확장하며 기존 좌표·바닥·오브젝트·상호작용을 보존한다. 변경 미리보기·적용·취소·되돌리기는 기존 편집기와 같은 경로를 쓴다. 모델 응답 동안 맵이 바뀌면 오래된 변경안은 적용하지 않는다. 서버는 실제 배치·충돌·이동 경로·스크립트 문법을 검증하고 실패 이유로 한 번 수정 요청한다.

없는 에셋은 `assets` 제작안으로 제안하며 가짜 에셋 ID를 배치하지 않는다. 바닥은 텍스처 1장, 벽·건물·가구는 두 시점 2장, 인물은 두 시점 스프라이트 시트를 만든다. 선택적 `w,h`로 바닥을 영역에 칠하거나 벽을 반복 배치한다. 반복 사용은 생성 장수를 늘리지 않는다. 제작 요청 → 교사 비용 승인·생성 → 보관함 저장 → 맵 배치 미리보기까지 연결된다. 교사가 직접 만든 요청도 별도 학생 계정 없이 자신의 요청으로 저장할 수 있다. 요청 키를 재사용한 전송은 같은 제작 요청으로 복구한다.

## 에이전트가 작성하는 맵 동작 코드

모델이 실제 JavaScript를 `setScript`에 작성한다. 변수·함수·배열·Set으로 개인 점수, 수집 아이템, 시간 제한, 미션 단계, 대화 분기를 구성할 수 있다. 다음 API를 제공한다.

- `World.onEnter(name, fn)`, `onLeave(name, fn)`, `onUpdate(fn)`: 위치·구역·플레이 경과 시간에 따른 동작.
- `World.onInteract(id/name/assetId, (ctx, object) => {})`: 근처 물체의 살펴보기 버튼.
- `World.onQuiz((result, ctx) => {})`: 문제 ID·문제·선택 번호·정답 여부.
- `World.completeQuiz(퀴즈상호작용id, 문구?)`: 해당 퀴즈를 완료 처리하고 판의 `?`를 완료 문구(기본 `완료`, 1~12자)로 교체한다. 다시 문제를 열 수 없으며 이 명령만으로 정답 점수는 주지 않는다. 오브젝트 ID가 아닌 상호작용 ID를 쓴다.
- `World.choose(id, title, choices)`와 `onChoice(id, (index, ctx) => {})`: 최대 5개 선택지, 취소는 -1.
- `World.hud(id, label, value)`: 최대 8개 진행 표시. 빈 label은 제거.
- `World.object(id/고유이름, {visible, blocking, x, y})`: 수집 후 숨기기, 문 통과 허용, 칸 단위 NPC 순찰·이동.
- `World.teleport(x, y)`: 현재 맵의 걸을 수 있는 칸으로 이동.
- 기존 `shake`, `reverseControls`, `vision`, `speed`, `message` 효과도 조합 가능.

`ctx.objects`에는 실제 오브젝트의 ID·에셋 ID·이름·현재 위치·보임·충돌 여부가 있다. 새로 제작할 에셋의 고유 이름을 코드에서 사용하면 생성·배치한 뒤 연결된다. 조건은 모델이 직접 코드로 작성하며 고정 예제만 선택하는 방식이 아니다.

기본 퀴즈는 정답을 맞히면 자동으로 판이 `완료`로 바뀌고 재풀이가 차단된다. 오답은 다시 풀 수 있다. 위에서 보기·입체 보기·회전에도 판의 완료 표시가 유지된다. 완료 상태와 점수는 학생 개인의 현재 플레이 안에서 맵별로 보관하므로 포털로 다른 맵에 갔다 돌아와도 유지되며, 새로 입장하거나 새로고침하면 초기화된다. 원본 맵이나 다른 학생의 진행은 변경하지 않는다. 에이전트에게 “맞힌 문제는 완료로 바꾸고 다시 열리지 않게 해줘”라고 요청할 수 있고, 별도 문구가 필요하면 `World.onQuiz(r=>{if(r.correct)World.completeQuiz(r.id,"해결!");});`처럼 구성한다. 기존 스크립트가 있으면 덮어 지우지 말고 그 안에 연결한다.

코드는 네트워크 없는 opaque iframe의 Worker에서 실행한다. DOM·계정·서버·교사 제어에 접근하지 못하며 시간 제한과 명령 형식·개수·경계 검증을 적용한다. 학생이 멈춤/검은 화면 상태면 코드의 시간·이동·대화 입력도 멈춘다. 물체 변경은 플레이 세션의 사본에만 적용하며 재입장하면 초기화된다. 플레이어 위치에 문을 닫아 가두는 변경은 적용하지 않는다. 실행 오류는 동작을 중지하고 원본 지형으로 복구한다.

생성된 코드에는 브라우저의 같은 격리 런타임으로 초기화·일부 구역/상호작용/선택/퀴즈를 실행하는 기본 검사가 추가됐다. 오류는 이전 변경안과 함께 모델에 한 번 보내 수정하며, 실패가 남으면 적용하지 않는다. 모든 조건과 긴 시간 경과를 증명하는 검증은 아니므로 실제 수업 전 플레이 확인이 필요하다. 서버 공통 점수, 외부 서비스 연결, 엔진 자체나 라이브러리를 자동 수정·배포하는 기능은 아직 제공하지 않는다. 지원하지 않는 기능을 구현했다고 모델이 주장하지 않도록 프롬프트에 범위를 명시한다.

## 생성 전 비용 견적과 승인

에이전트 제작안에는 개별/합계 예상 금액을 먼저 표시한다. 실제 생성 버튼은 서버에서 현재 요청의 견적을 받아 표시한 뒤 활성화된다. `GET /requests/{id}/generate`가 제공한 `quoteId`를 `POST`에 포함해야 한다. 해시는 승인 대상 스냅샷·수정 번호·시도 번호·모델·견적을 묶으므로 내용이 바뀌면 다시 확인해야 한다. 승인 교사·시각·견적은 생성 작업과 같은 트랜잭션으로 저장한다. 동일 멱등 키 재전송은 기존 작업을 반환하며 재생성은 새 견적과 별도 클릭을 요구한다. 견적 없는 요청은 생성 큐에 등록하지 않는다. 작업 실행 시 승인한 모델이 바뀌어 있으면 유료 호출 전 중단한다.

단가는 [OpenAI 공식 이미지 생성 문서](https://developers.openai.com/api/docs/guides/image-generation)의 2026-10-22 확인값을 사용한다. 현재 설정인 GPT Image 2.5 Flare, medium, 1024×1024는 출력 439토큰/장이다. 견적 범위는 출력 비용에 설명 입력(UTF-8 바이트 수의 1/4~1배 토큰 가정), 참조 이미지(장당 1,000~5,000 입력 토큰 가정)를 더한 **계획용 추정**이며 청구 상한 보장이 아니다. 대화 모델·재생성·세금 등은 별도이며 실제 이미지 사용량/확인 금액은 기존 완료 기록에서 확인한다. 알 수 없는 모델·단가는 0으로 표시하지 않고 생성 승인을 막는다. `OPENAI_IMAGE_PRICING` 설정도 동일 견적·사용량 계산에 반영한다.

node --test scripts/jamworld/browser.test.cjs scripts/jamworld/agent-design-browser.test.cjs scripts/jamworld/agent-code-browser.test.cjs scripts/jamworld/map-effects.test.cjs scripts/jamworld/workshop-live-browser.test.cjs

## 수업 기록 → 분석 → 다음 수업 → 맵 (2026-10-22)

CLI 0.2.0의 `learningcrew lesson prepare 차시ID --class 학급ID --goal "다음 목표" --minutes 40 --output lesson.moa.json`으로 읽기 전용 수업 기록 파일을 만든다. 기존 MCP 로그인·권한 확인을 사용하고 모델이나 이미지 생성은 호출하지 않는다. 이름을 학생 코드로 바꾸고 이메일·링크를 생략하며 활동별로 균형 있게 최대 120개 응답을 포함한다. 원본 수업·학생 응답에는 쓰지 않는다.

편집기 도우미의 **수업 기록 불러오기**에서 파일을 열고 수업 조건을 확인한 뒤 **분석하고 다음 수업 설계**를 누른다. 파일을 여는 것만으로 생성 요청이 발생하지 않는다. 다음 호출에서 기존 AI 맵 도우미가 관찰 사실·확인이 필요한 해석·다음 목표·단계별 활동을 `lessonReview`로 반환하면서 실제 맵 작업도 제출한다. 부족한 정보가 있으면 추가 질문을 먼저 할 수 있다. 맵은 기존 미리보기·적용·되돌리기를 사용하며 에셋은 기존 제작안·견적·승인 흐름을 따른다.

UI는 분석마다 근거 ID를 펼쳐 원문을 확인할 수 있게 한다. 서버는 현재 교사의 해당 러닝크루 학급 멤버십을 확인하고, 근거 ID가 실제 포함된 기록에 있는지와 활동 시간 합을 검증한다. 실패하면 모델에 한 번 수정 요청하고 실패가 남으면 미리보기를 만들지 않는다. 근거 존재 검증이 교육적 해석의 정확성까지 보장하는 것은 아니다. 모델에는 학생별 정보를 공유 맵에 직접 인용하지 않고 일반 학습 내용으로 변환하도록 지시한다. 원본 기록은 별도 맵 필드에 내장하지 않는다.

파일은 수집 시점의 스냅샷이다. 표본·전체 개수와 포함 응답자를 구분하고, 채점 가능한 객관식만 정답을 다시 계산한다. 파일과 분석은 계정·프로젝트·맵별 브라우저 대화에 저장되고 재접속 때 이어진다. 새 기록을 불러오면 이전 기록과 분석의 연결을 교체해 같은 근거 ID가 다른 원문을 가리키지 않게 한다.

검증: 핵심 테스트 77개, CLI 테스트 13개, 기존 에이전트 회귀와 실제 CLI→MCP→브라우저 가져오기→서버 근거 수정→맵 적용·저장·재접속을 확인했다. 통합 테스트 `scripts/jamworld/lesson-bridge-browser.test.cjs`는 별도 demo Firebase에만 자료를 만들고 모델 응답을 대체한다. 실제 학생 기록과 유료 이미지 호출은 사용하지 않는다.
