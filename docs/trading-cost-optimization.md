# 트레이딩 및 게임 비용 최적화

## 변경 사항

- 랭킹은 30초간 학급 단위로 공유한다. 서버 전용 `tradingRankingCache/{cid}`에 저장하며, 캐시 조회 전 호출자의 학급 멤버 권한을 매번 확인한다.
- 갱신 lease를 Firestore 트랜잭션으로 획득해 여러 함수 인스턴스의 중복 집계를 막는다. 갱신 중에는 기존 결과를 반환하며 첫 집계는 제한된 시간만 기다린다. 실패하면 lease를 해제하고, 프로세스 종료 시 60초 후 재시도할 수 있다.
- `positions/{uid}.invested`는 수수료를 포함한 누적 매수금액이다. 매수 체결 트랜잭션에서 증가하고 매도 시 유지된다. 중복 tradeId는 증가시키지 않는다.
- 기존 계좌는 최초 랭킹 조회 또는 거래 시 해당 학생의 거래 이력을 한 번 집계한다. 포지션과 이력을 같은 트랜잭션에서 읽어 거래와 경합하면 재시도한다. 기존 5,000건 상한을 사용하지 않는다. 초기 이관에는 일시적인 읽기와 학생당 문서 쓰기가 발생한다.
- 학생 계좌와 교사 표도 invested가 있으면 사용하고, 이관 전에는 기존 계산으로 폴백한다.
- 닫힌 PC 랭킹 서랍은 자식 컴포넌트를 마운트하지 않는다. 학급 체결 피드는 표시할 때만 구독한다.
- 랭킹은 표시 중인 탭에서만 30초 주기로 호출하며, 응답 대기 중에는 추가 호출하지 않는다. 실제 집계 시각을 표시한다. 거래 체결 직후 즉시 순위에 반영되지는 않는다.
- 학생 트레이딩과 교사 투자 현황은 숨겨진 브라우저 탭에서 구독을 중단한다. 복귀 시 재연결한다. Firestore의 재연결 과금 정책 때문에 모든 재접속 읽기가 없어지는 것은 아니다.
- 게임 활동 기록은 5초에서 10초로 줄인다. 기존 20초 응답 판정은 유지한다. 숨김/포커스 이탈은 즉시 기록하며 중복 상태 이벤트를 합치고 쓰기 순서를 유지한다.

## 예상 읽기 구조

정상 캐시 적중: 요청당 멤버 문서 1개 + 캐시 문서 1개. 캐시 갱신 시 포지션·멤버 목록·시세를 읽지만 이관 후 거래 이력은 읽지 않는다. 트랜잭션 재시도와 최초 이관은 별도다. 이는 코드/가짜 저장소 검증 결과이며 운영 청구서에서 측정한 절감액은 아니다.

## 검증

```sh
npm --prefix functions run build
node --test tests/trading-cost.test.cjs tests/trade-insights.test.cjs
npm run build
```

비용 테스트는 실제 callable 구현을 가짜 Firestore 경계와 연결한다. 동시 호출 캐시 공유, 실패 복구, 대기 상한, 이전 계좌 이관, 캐시 적중 읽기 수, 캐시 만료 후 이력 조회 제거, 권한 재검증, 중복 거래와 전량 매도를 확인한다. 실제 Firestore 에뮬레이터의 경합/부하 테스트를 대체하지는 않는다.

## 배포와 운영 확인

서버 변경은 `getTradingRanking`과 `executeTrade`를 함께 배포해야 한다. 기존 Hosting 전용 배포만으로는 서버 비용 최적화가 적용되지 않는다. 관련 코드 검토 후 다음 순서로 배포할 수 있다.

```sh
npm run build
firebase deploy --only functions:getTradingRanking,functions:executeTrade
firebase deploy --only hosting
```

현재 작업에서는 배포하지 않았다. 배포 후 학급의 최초 이관이 끝난 다음 Firestore 읽기/쓰기와 함수 호출 수를 비교한다. 캐시 오류·초기 이관 시간·랭킹 집계 시각도 확인한다. 학생별 거래 이력 1,000건 구독 구조와 외부 AI 호출 정책은 별도 개선 영역으로 남아 있다. 히트맵 수집은 추가하지 않았다.
